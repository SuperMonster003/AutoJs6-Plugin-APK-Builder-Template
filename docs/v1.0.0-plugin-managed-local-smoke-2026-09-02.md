# v1.0.0 设备内插件托管构建本地验收（2026/09/02）

## 1. 结论与范围

本轮本地 Debug 验收通过，证明新的 AutoJs6 候选在旧实验 remote 开关保持默认关闭时，可以从普通“打包应用”入口调用
设备内 APK Builder 插件，完成构建、签名、宿主输出复核、安装与冷启动。

这不是生产签名候选验收，不替代 M7-4/M7-6：未运行受信候选工作流，未创建 Release/tag，未写入
`compat-matrix.json`，也未推进 `version.properties`。维护者确认新的精确宿主 SHA 后，才允许执行候选专用受信流水线。

## 3. 插件设备回归

`RemoteApkBuildSessionInstrumentedTest` 在 G8441 上通过 45/45，耗时 176.602 秒。覆盖内容包括：

- `supportsApkBuild=true`、`apkBuilderBuildProtocolVersion=3`、`apkBuilderBuildExecutionMode=on-device-plugin`；
- `supportsRemoteBuild=false` 的旧兼容关闭语义不影响正式能力；
- BKS/JKS 创建、校验与错误别名失败关闭；
- V1/V2、自定义密钥库、图标、Runtime Kit ABI 选择与基础 native 输入；
- 输入 size/SHA-256、ZIP 路径/数量/解压边界、Parcelable/JSON/Manifest/ARSC 边界；
- TypeScript 暂存认证、敏感值收口、取消、FD 与工作区清理。

迁移过程中修正了三个测试夹具问题：旧 remote 协议错误措辞、畸形 ZIP 在进入被测代码前由夹具自行解析、以及把已迁移给独立
OpenCV/图像量化插件的 native 库误当作 Runtime Kit 模板内置库。最终 arm64 产物的完整设备类无跳过、无失败。

## 4. 普通打包与运行闭环

Fresh install 后，AutoJs6 默认 SharedPreferences 中不存在 `key_$_apk_builder_remote_build_enabled`，因此旧实验开关按代码默认值
保持 `false`。从文件页对单文件脚本选择“Build APK”，未进入开发者设置，也未开启旧 remote 开关。

最终一轮 UI 进度为：准备 4.1 秒、插件构建 0.6 秒、签名 11.0 秒、清理 0.3 秒。构建对话框显示插件私有目录中的 unsigned
中间文件，并由宿主原子发布到：

`/storage/emulated/0/Scripts/CodexPluginBuildSmoke-20260902_v1.0.0.apk`

`apksigner` 独立验证通过，`adb install -r` 成功。冷启动链路到达生成应用自身的
`SplashActivity -> ScriptExecuteActivity`；前台 UI 唯一命中 `PLUGIN BUILD SMOKE OK`，logcat 同名哨兵命中，且该次启动没有
`FATAL EXCEPTION`。

Android 9 上第一次从宿主安装按钮跳转时，系统要求开启“允许此来源”；权限切换前建立的旧安装会话随后报告
`Base APK has no verifiable signer`。这与 2026/08/31 已记录的系统安装会话边缘现象一致；同字节 APK 随后通过独立
`apksigner` 与 `adb install`。该现象不改变构建/签名结论，但仍应在正式候选设备验收中复测宿主安装入口。
