- 日期: 2026/09/01
- 结论: **Rejected / No-Go**
- 候选用途: M7 首个正式发布前的隔离签名候选
- AutoJs6 精确源提交: `71e684b8dc1a59783293e0ad282638e3a88e37b6`
- 插件提交: `2796cbf44deee913ae8bfae4b4a7c5dcea820d48`

## 1. 审计结论

候选的来源固定、Runtime Kit 集合、生产签名、五 ABI 资产、APK 元数据、内嵌资产与机器可读 evidence 均通过。
但是实体设备在核心打包场景中无法进入模板传输或构建阶段, 因而不能满足 M7-6。

失败不是设备或签名问题。宿主已正确发现、信任并启用匹配的官方插件, 但 AutoJs6 当前普通打包入口只解析和调用实验性
远程构建会话。该会话同时受两个 R0 门禁控制:

1. 宿主开发者选项中的远程 APK 构建总开关默认关闭;
2. 官方插件候选按发布策略声明 `supportsRemoteBuild=false`。

AutoJs6 提交 `b2fd2b6ae` 又已移除完整的宿主进程内构建器。因此, 在 M7 要求“远程构建保持不可用”的前提下,
当前代码不存在可完成普通 APK 打包的第二条执行路径。将远程开关改为默认开启或让正式插件提前上报远程能力都会越过
M8 的安全审查、预览周期、独立回退和维护者签字门槛, 不能作为本候选的发布修补。

发布判定如下:

- `71e684b8d` 保留为内容固定、证据完整但已拒绝的 AutoJs6 v6.8.0 候选;
- 五个签名插件 APK 保留为候选审计证据, 不提升为正式资产;
- 不运行正式发布工作流, 不写权威兼容矩阵, 不推进版本序号;
- 替代候选必须先恢复或实现一条不依赖实验性远程能力的打包路径, 然后以新的精确 AutoJs6 源 SHA 重做全部候选与装机验收。

## 4. 实体设备验收

### 4.1 环境与前置状态

- 设备: Sony G8441
- Android: 9 / API 28
- ABI: arm64-v8a
- 序列号: `BH900ASK9E`
- 宿主: 从精确提交 `71e684b8d` 构建的 AutoJs6 `6.8.0 / 5277` arm64 debug APK
- 插件: 上表官方生产签名 arm64-v8a 候选
- 初始状态: 宿主和目标插件均未安装

宿主 APK SHA-256 为
`014100417d22ab8657b8d521cddc413e2fb1c85101f54b4688a25b73bfe5605c`。插件安装后, Plugin Center 正确显示:

- `1.0.0+autojs6-6.8.0 (527701)`;
- engine `apk-builder-template` / engine ID `autojs6-apk-builder-template`;
- `requiresHostVersion=5277`;
- variant `inrt-arm64-v8a`, supported ABI `arm64-v8a`;
- 官方签名门禁通过且启用开关为开。

### 4.2 失败现象

在 BuildActivity 中选择脚本并点击打包后, 宿主在构建开始前显示:

- `APK Builder template is unavailable`;
- `no enabled, official, compatible APK Builder plugin was found`;
- `Remote APK building is disabled by the AutoJs6 developer switch.`

重新唤醒插件服务、打开 Plugin Center 并重启宿主后结果不变。没有模板传输, 没有输出 APK, 因而无法继续安装与冷启动烟测。

### 4.3 源码归因

精确候选中的调用链为:

1. `TemplateApkResolver.resolve()` 调用 `ApkBuilderTemplatePluginHost.resolveRemoteBuilder()`;
2. `resolveRemoteBuilder()` 在 `RemoteApkBuildRuntimeGate.isEnabled()==false` 时立即返回 `null`;
3. 即使手动打开宿主开关, 官方候选仍因 `supportsRemoteBuild=false` 被远程候选筛选器排除;
4. `BuildActivity.callApkBuild()` 后续无条件调用 `RemoteApkBuildClient.buildBlocking()`;
5. `b2fd2b6ae` 已移除原完整 `ApkBuilder`; 当前同名类只是远程协议兼容适配器, 不能作为独立本地路径。

这与 `docs/remote-build-fallback-decision.md` 已记录的架构事实一致, 但与 M7 同时要求“远程不可用”和“普通打包成功”相冲突。

## 6. 下一决策

推荐将“一条不依赖实验性远程能力的可靠打包路径”前移为 M7 发布前置, 优先评估恢复并维护宿主本地构建器或等价的独立实现。
这会产生新的 AutoJs6 源提交, 必须重新固定候选 SHA, 重跑五 Runtime Kit、五签名插件资产以及真实设备/AVD 验收。

不推荐为了保留 `71e684b8d` 而默认开启远程开关、伪装远程会话为普通模板路径, 或让正式插件在 M8 门槛通过前声明
`supportsRemoteBuild=true`; 三种做法都会削弱已经建立的安全与放量门禁。
