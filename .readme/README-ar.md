### مقدمة

******

تحول ميزة "تغليف التطبيق" في AutoJs6 السكربت أو المشروع إلى ملف APK يثبت ويعمل بشكل مستقل, دون الحاجة إلى AutoJs6 على الجهاز الهدف. يحتاج التغليف إلى "APK قالب" كهيكل أساسي: تطبيق يحتوي مسبقا على بيئة تشغيل السكربتات الكاملة. وللحفاظ على صغر حجم التطبيق الرئيسي, لم تعد إصدارات AutoJs6 الحديثة تضمن هذا القالب الكبير; بل انتقل إلى هذا المكون, ولا يثبته إلا المستخدمون الذين يحتاجون إلى التغليف.

ليس للمكون أيقونة ولا واجهة. كل شيء يجري في الخلفية: عند التغليف يكتشف AutoJs6 المكون, ويتحقق من توافق الإصدارات وسلامة الملفات, ثم يقرأ APK القالب المدمج لإتمام العملية.

دليل سريع في سطر واحد: إذا كنت تستخدم "تغليف التطبيق", فثبت البنية التي اختارها مركز المكونات لإصدار AutoJs6 لديك وفق مصفوفة التوافق; وإذا كنت لا تغلف تطبيقات مستقلة أبدا فلا حاجة لك به.

******

### كيف يعمل

******

عند تغليف تطبيق مستقل, يتعاون AutoJs6 مع هذا المكون على النحو التالي:

1. الاكتشاف: يحدد AutoJs6 مكون القالب المثبت ويقرأ بياناته الوصفية
2. فحص التوافق: تقارن الإصدارات وإصدارات البروتوكول واسم حزمة القالب; وأي اختلاف ينتج تحذيرا أو يمنع التغليف
3. فحص السلامة: يتحقق من ملخص SHA-256 لملف APK القالب لاستبعاد الملفات التالفة أو المعدلة
4. نقل القالب: يمرر APK القالب تدفقيا عبر أنبوب بين العمليات دون نسخ مؤقتة
5. التغليف: يكتب AutoJs6 السكربت والإعدادات والموارد في القالب وينتج APK المستقل النهائي

******

### الميزات

******

- يوفر قالب التطبيق المستقل الكامل (Runtime Kit) لميزة "تغليف التطبيق" في AutoJs6; لا حاجة إلى أي إعداد بعد التثبيت.
- تحتفظ كل بنية من المكون في اسم إصدارها بمضيف AutoJs6 الذي بُنيت له فعليا (مثل 1.0.0+autojs6-6.8.0-alpha5), ويمكنها أن تعلن صراحة نطاق تصحيحات مغلقا تم التحقق منه; لا يظهر تحذير عند التطابق التام, ويظهر تحذير لمضيف آخر داخل النطاق, ويُمنع المضيف الواقع خارجه.
- حماية سلامة مزدوجة: تتحقق ملخصات SHA-256 والمدخلات المطلوبة للقالب عند بناء المكون, ويبلغ ملخص القالب إلى AutoJs6 لإعادة التحقق عند التغليف.
- يمرر القالب إلى AutoJs6 تدفقيا عبر أنبوب بين العمليات دون نسخ مؤقتة زائدة.
- يتضمن مخزن مفاتيح افتراضيا, بحيث يمكن إنتاج APK قابل للتثبيت حتى قبل إعداد مفتاح توقيع مخصص.
- يدعم بروتوكول "البناء عن بعد" التجريبي الذي ينفذ فيه المكون بناء خفيفا بنفسه (معطل افتراضيا; انظر الحدود).
- تغطي بيانات المكون وتعليمات الاستخدام و README و CHANGELOG عشر لغات: الصينية المبسطة, والصينية التقليدية (هونغ كونغ/تايوان), والإنجليزية, والفرنسية, والإسبانية, واليابانية, والكورية, والروسية, والعربية.

### البدء السريع

******

- **كيف تثبته**: يفضل التثبيت من مركز مكونات AutoJs6: تقرأ بنى المضيف المدعومة مصفوفة التوافق وتختار تلقائيا إصدار المكون المقترن وملف ABI المطابق للجهاز, مع الرجوع إلى universal عند غيابه. للتثبيت اليدوي, نزل ملف APK من صفحة [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-APK-Builder-Template/releases) وحدد المضيف المقترن من وسم الإصدار الذي يحمل اسم AutoJs6 أو من اللاحقة autojs6- في إصدار المكون (مثلا: المكون v1.0.0+autojs6-6.8.0-alpha5 يقترن بـ AutoJs6 v6.8.0 Alpha5). إذا اختار مركز المكونات إصدارا أقل من المثبت, فاتبع إرشادات إلغاء التثبيت ثم إعادة التثبيت لأن Android لا يسمح بالكتابة فوق التطبيق بإصدار أقدم.
- **كيف تستخدمه**: لا خطوات إضافية. استخدم ميزة "تغليف التطبيق" في AutoJs6 كالمعتاد; وسيكتشف مسار التغليف المكون ويستخدم قالبه المدمج تلقائيا.
- **كيف تتأكد أنه يعمل**: بدون المكون (أو مع إصدار غير مطابق) يطلب منك مدخل التغليف في AutoJs6 تثبيته أو تفعيله; وبعد تثبيت الإصدار المطابق يختفي التنبيه, مما يعني أن المكون معروف. ليس للمكون أيقونة ولا واجهة, لذا فعدم ظهوره على الشاشة الرئيسية أمر طبيعي.
- **أين تنظر عند الفشل**: عند ظهور تحذير توافق, استخدم البنية التي اختارها مركز المكونات وفق مصفوفة التوافق أو تحقق من أن المضيف الحالي داخل النطاق الذي يعلنه المكون; وإذا أدى عدم التوافق إلى منع التغليف فثبت البنية المطابقة للمصفوفة; وعند خطأ في التحقق أو تلف القالب, أعد تثبيت المكون من مصدر رسمي; ولأي شيء آخر افتح [بلاغا](https://github.com/SuperMonster003/AutoJs6-Plugin-APK-Builder-Template/issues) مرفقا بسجلات AutoJs6 وخطوات إعادة الإنتاج.

### الحدود

******

تجنبا لسوء الفهم, تقع الأمور التالية صراحة خارج نطاق هذا المكون:

- لا يمكن استخدام المكون بمفرده: فليس له أيقونة ولا واجهة, ولا يستدعيه إلا AutoJs6 أثناء التغليف.
- لا ينشئ المكون APK القالب: فالقالب و Runtime Kit يبنيهما وينشرهما مستودع AutoJs6 الرئيسي; وهذا المكون يتحقق منهما ويغلفهما ويوزعهما فقط.
- لا يشارك المكون في كتابة السكربتات أو تشغيلها اليومي: ميزة "تغليف التطبيق" وحدها تقرؤه.
- البناء عن بعد تجريبي ومعطل افتراضيا: الإصدارات الرسمية للمكون لا تفعله; وهو متاح فقط في المكونات المبنية ذاتيا مع تفعيل الميزة صراحة.
- لا يخفف المكون متطلبات الإصدارات: قد يمنع التغليف مع إصدار AutoJs6 غير مطابق, وحتى إن نجح فلا يضمن عمل الناتج.

### الأسئلة الشائعة

******

**س: كيف يختار مركز المكونات بنية المكون؟**

ج: تستعلم إصدارات AutoJs6 المدعومة عن compat-matrix.json باستخدام versionCode الخاص بها, وتختار البنية ذات أعلى pluginVersionCode ضمن نطاق التوافق, ثم تفضل ABI المطابق للجهاز وترجع إلى universal عند غيابه. لا يمكن لإدخال المصفوفة تغطية نطاق تصحيحات تم التحقق منه إلا عند التصريح صراحة بـ allowPatchVersionMismatch=true: يحزم مضيف البناء المطابق من دون تحذير, ويعيد مضيف آخر داخل النطاق استخدام البنية نفسها مع تحذير, ولا يمكن لمضيف خارج النطاق استخدامها. إذا لم يوجد إدخال صالح في المصفوفة يبقى مسار Release/الوسم الحالي هو البديل. إذا كان إصدار المكون المقترن أقل من الإصدار المثبت, يطلب مركز المكونات إلغاء التثبيت أولا ثم تثبيت البنية المقترنة لأن Android لا يمكنه خفض الإصدار فوق التطبيق الحالي.

**س: لماذا يجب أن يقترن المكون بإصدار AutoJs6 لدي؟**

ج: بيئة تشغيل السكربتات داخل APK القالب تقابل واجهة تشغيل AutoJs6 مقابلة صارمة, لذا يحدد التوافق عقد versionCode الذي يعلنه المكون ويجتاز التحقق, لا الإصدار الدلالي الخاص بالمكون. تستهدف معظم البنى مضيفا واحدا بعينه; ويمكن للبنية أيضا أن تعلن صراحة نطاقا مغلقا ومتحققا منه لإصدارات التصحيح. عندئذ يمر المضيف المرجعي بلا تحذير, وتتلقى المضيفات الأخرى داخل النطاق تحذيرا, ويمنع ما يقع خارجه. يتطور إصدار المكون الخاص (مثل 1.0.0) بشكل مستقل, بينما تدل اللاحقة autojs6- في اسم الإصدار ووسم الإصدار على المضيف المقترن; وعند استخدام AutoJs6 قديم نزل بنية المكون من الوسم القديم الموافق (وللرجوع من مكون أحدث ألغ تثبيته أولا; فنظام Android لا يسمح بالتثبيت مع خفض الإصدار).

**س: لا أجد المكون على الشاشة الرئيسية. هل فشل التثبيت؟**

ج: لا. ليس للمكون أيقونة ولا واجهة, ويعمل كخدمة خلفية لـ AutoJs6 فقط. يمكنك التأكد منه في قائمة "الإعدادات > التطبيقات" باسم APK Builder Template.

**س: يبلغ التغليف عن فشل التحقق من القالب. ماذا أفعل؟**

ج: يعني هذا عادة أن المكون المثبت ناقص أو تالف. أعد تثبيته من مركز مكونات AutoJs6 أو من Releases في هذا المستودع; وإذا استمرت المشكلة فافتح بلاغا.

**س: لماذا حجم المكون كبير هكذا؟**

ج: لأنه يتضمن قالب تطبيق مستقل كاملا, بما فيه محرك السكربتات والمكتبات الأصلية لجميع معماريات المعالجات. وهذا بالضبط سبب فصل القالب عن تطبيق AutoJs6 الرئيسي: فلا يتحمل هذا الحجم إلا من يستخدم ميزة التغليف.

**س: ما "البناء عن بعد"؟**

ج: بروتوكول تجريبي يتيح للمكون تنفيذ بناء خفيف داخل عمليته الخاصة (فك القالب, وكتابة السكربت والإعدادات, وإعادة كتابة اسم الحزمة والموارد, وإعادة التوقيع). تبقيه الإصدارات الرسمية معطلا; وهو موجه حاليا للمطورين الذين يبنون المكون بأنفسهم.

### مرجع تقني

******

الأقسام التالية موجهة لمطوري المكونات والمدمجين; ولا يحتاج إليها عادة من يستخدم المكون فقط.

#### Runtime Kit

يبنى Runtime Kit في مستودع AutoJs6 الرئيسي وهو مصدر الحقيقة الوحيد لقالب التطبيق المستقل. يتحقق هذا المكون من ذلك الأثر ويغلفه فقط; ولا ينشئ `template.apk`. يحتوي Runtime Kit الكامل عادة على هذه الملفات:

```text
template.apk
template.apk.sha256
default_key_store.bks
default_key_store.bks.sha256
runtime-kit.json
build-contract.json
public-api.txt
assets-manifest.json
native-libs.json
provenance.json
```

#### معرفات الاكتشاف

يكتشف المضيف هذا المكون ويرتبط به عبر المعرفات التالية:

```text
Plugin ID:  autojs6-apk-builder-template
Engine:     apk-builder-template
Variant:    inrt-universal
Actions:    org.autojs.plugin.INFO / org.autojs.plugin.APK_BUILDER
Template:   org.autojs.autojs6.inrt
```

#### البناء المحلي

أنشئ Runtime Kit من مستودع AutoJs6 الرئيسي أولا:

```powershell
.\gradlew.bat --console=plain :app:generateRuntimeKit
```

ثم ابن هذا المستودع مع تحديد دليل Runtime Kit الناتج:

```powershell
.\gradlew.bat --console=plain :app:assembleRelease `
  -Pautojs.apkBuilder.templatePlugin.runtimeKitDir=<runtime-kit-dir>
```

يمكنك أيضا فك ضغط `autojs6-runtime-kit-*.zip` منشور إلى `runtime-kit/` ثم البناء مباشرة:

```powershell
.\gradlew.bat --console=plain :app:assembleRelease
```

#### مسار الإصدار

مسار إصدار الإنتاج المتوقع هو:

```text
AutoJs6 tag
-> main repository generates autojs6-runtime-kit-*.zip
-> main repository uploads the Runtime Kit to its GitHub Release
-> main repository dispatches SuperMonster003/AutoJs6-Plugin-APK-Builder-Template
-> this repository downloads and verifies the Runtime Kit
-> this repository builds the plugin APK
-> this repository uploads the plugin APK to the same tag Release
-> this repository records the pairing into compat-matrix.json
-> AutoJs6 Plugin Center installs this plugin
```

#### التوقيع

يجب توقيع إصدارات الإنتاج للمكون بمفتاح توقيع مكونات AutoJs6 الموثوق. تتطلب إصدارات GitHub Actions أسرار المستودع التالية:

```text
SIGNING_KEY_BASE64
SIGNING_KEY_STORE_PASSWORD
SIGNING_KEY_ALIAS
SIGNING_KEY_PASSWORD
SIGNING_CERT_SHA256
```

ما زالت بنى الإصدار المحلية تدعم ملف الجذر المتجاهل `sign.properties`:

```properties
storeFile=/absolute/path/to/release.jks
storePassword=...
keyAlias=...
keyPassword=...
```
