### Введение

******

Функция AutoJs6 "Упаковать приложение" превращает скрипт или проект в APK, который устанавливается и работает самостоятельно, без AutoJs6 на целевом устройстве. Для упаковки нужен "шаблонный APK" в качестве каркаса: приложение, уже содержащее полную среду выполнения скриптов. Чтобы главное приложение оставалось компактным, свежие версии AutoJs6 больше не включают этот объемный шаблон; теперь он живет в этом плагине и устанавливается только теми, кому нужна упаковка.

У плагина нет ни значка, ни интерфейса. Все происходит в фоне: при упаковке AutoJs6 обнаруживает плагин, проверяет совместимость версий и целостность файлов, затем читает встроенный шаблонный APK и завершает упаковку.

Краткий ориентир: если пользуетесь функцией "Упаковать приложение", установите сборку, выбранную Центром плагинов для вашего AutoJs6 по матрице совместимости; если вы никогда не упаковываете автономные приложения, он вам не нужен.

******

### Как Это Работает

******

При упаковке автономного приложения AutoJs6 и этот плагин взаимодействуют так:

1. Обнаружение: AutoJs6 находит установленный плагин с шаблоном и читает его метаданные
2. Проверка совместимости: сравниваются версии, версии протокола и имя пакета шаблона; при расхождении выдается предупреждение или упаковка блокируется
3. Проверка целостности: сверяется дайджест SHA-256 шаблонного APK, чтобы исключить поврежденные или подмененные файлы
4. Передача шаблона: шаблонный APK передается потоком через межпроцессный канал, без временных копий
5. Упаковка: AutoJs6 записывает скрипт, настройки и ресурсы в шаблон и создает итоговый автономный APK

### Возможности

******

- Предоставляет полный шаблон автономного приложения (Runtime Kit) для функции AutoJs6 "Упаковать приложение"; после установки настройка не требуется.
- Каждая сборка плагина сохраняет в имени хост AutoJs6, для которого она создана (например, 1.0.0+autojs6-6.8.0-alpha5), и может явно объявить проверенный закрытый диапазон исправлений; точное совпадение не требует предупреждения, другой хост внутри диапазона получает предупреждение, а хост вне диапазона блокируется.
- Двойная защита целостности: при сборке плагина проверяются дайджесты SHA-256 и обязательные элементы шаблона, а при упаковке дайджест шаблона сообщается AutoJs6 для повторной проверки.
- Шаблон передается в AutoJs6 потоком через межпроцессный канал без лишних временных копий.
- Содержит хранилище ключей по умолчанию, поэтому установочный APK можно получить даже без настройки собственного ключа подписи.
- Поддерживает экспериментальный протокол "удаленной сборки", при котором процесс плагина самостоятельно выполняет облегченную сборку (по умолчанию отключено; см. Границы).
- Метаданные плагина, инструкции, README и CHANGELOG охватывают 10 языков: упрощенный китайский, традиционный китайский (Гонконг/Тайвань), английский, французский, испанский, японский, корейский, русский и арабский.

### Быстрый Старт

******

- **Как установить**: По возможности устанавливайте из Центра плагинов AutoJs6: поддерживаемые сборки хоста читают матрицу совместимости и автоматически выбирают сопряженную версию плагина и точный ABI-артефакт устройства, а при его отсутствии используют universal. Для ручной установки скачайте APK со страницы [Releases](https://github.com/SuperMonster003/AutoJs6-Plugin-APK-Builder-Template/releases) и определите сопряженный хост по тегу с именем версии AutoJs6 или по суффиксу autojs6- в версии плагина (например, плагин v1.0.0+autojs6-6.8.0-alpha5 работает в паре с AutoJs6 v6.8.0 Alpha5). Если Центр плагинов выбрал версию ниже установленной, следуйте подсказке об удалении и повторной установке, поскольку Android не допускает установку с понижением поверх приложения.
- **Как пользоваться**: Никаких дополнительных действий. Используйте функцию "Упаковать приложение" в AutoJs6 как обычно; процесс упаковки сам обнаружит плагин и использует его встроенный шаблон.
- **Как убедиться, что все работает**: Без плагина (или при несовпадении версий) вход в упаковку в AutoJs6 предложит установить или включить его; после установки подходящей версии подсказка исчезает — значит, плагин распознан. У плагина нет значка и интерфейса, поэтому его отсутствие на рабочем столе — это норма.
- **Куда смотреть при сбое**: При предупреждении о совместимости используйте сборку, выбранную Центром плагинов по матрице совместимости, либо убедитесь, что текущий хост входит в заявленный плагином диапазон; если несовместимость блокирует упаковку, установите соответствующую матрице сборку; при ошибке проверки или повреждении шаблона переустановите плагин из официального источника; в остальных случаях создайте [issue](https://github.com/SuperMonster003/AutoJs6-Plugin-APK-Builder-Template/issues), приложив журналы AutoJs6 и шаги воспроизведения.

### Границы

******

Во избежание недоразумений следующее явно выходит за рамки этого плагина:

- Плагин нельзя использовать сам по себе: у него нет значка и интерфейса, его вызывает только AutoJs6 при упаковке.
- Плагин не создает шаблонный APK: шаблон и Runtime Kit собирает и публикует основной репозиторий AutoJs6; этот плагин лишь проверяет, упаковывает и распространяет их.
- Плагин не участвует в написании и повседневном выполнении скриптов: его читает только функция "Упаковать приложение".
- Удаленная сборка экспериментальна и по умолчанию отключена: в официальных выпусках плагина она не включена и доступна только в самостоятельно собранных плагинах с явно включенной опцией.
- Плагин не смягчает требования к версиям: упаковка с несовпадающей версией AutoJs6 может быть заблокирована, а даже при успехе работоспособность результата не гарантируется.

### Частые Вопросы

******

**В: Как Центр плагинов выбирает сборку?**

О: Поддерживаемые версии AutoJs6 запрашивают compat-matrix.json со своим versionCode, выбирают сборку с наибольшим pluginVersionCode в совместимом диапазоне, затем предпочитают точный ABI устройства и при его отсутствии используют universal. Запись может охватывать проверенный диапазон исправлений только при явном allowPatchVersionMismatch=true: точный хост сборки упаковывает без предупреждения, другой хост внутри диапазона использует ту же сборку с предупреждением, а хост вне диапазона не может ее использовать. Если пригодной записи матрицы нет, сохраняется существующий канал Release/тег. Если сопряженная версия плагина ниже установленной, Центр плагинов предлагает сначала удалить плагин, а затем установить сопряженную сборку, поскольку Android не может выполнить понижение версии поверх приложения.

**В: Почему плагин должен быть сопряжен с моей версией AutoJs6?**

О: Среда выполнения скриптов внутри шаблонного APK строго соответствует runtime-API AutoJs6, поэтому совместимость определяется заявленным и проверенным контрактом versionCode плагина, а не его собственной семантической версией. Большинство сборок рассчитано на один точный хост; сборка также может явно заявить проверенный замкнутый диапазон патч-версий. Тогда опорный хост проходит без предупреждения, другие хосты внутри диапазона получают предупреждение, а хосты вне диапазона блокируются. Собственная версия плагина (например, 1.0.0) развивается независимо, а суффикс autojs6- в имени версии и тег релиза указывают сопряженный хост; на старом AutoJs6 скачивайте сборку плагина из соответствующего старого тега (чтобы вернуться с более нового плагина, сначала удалите его — Android не допускает установку с понижением версии).

**В: Я не вижу плагин на рабочем столе. Установка не удалась?**

О: Нет. У плагина нет значка и интерфейса, он работает только как фоновый сервис для AutoJs6. Убедиться в установке можно в списке "Настройки > Приложения" под именем APK Builder Template.

**В: Упаковка сообщает об ошибке проверки шаблона. Что делать?**

О: Обычно это означает, что установленный плагин неполон или поврежден. Переустановите его из Центра плагинов AutoJs6 или из Releases этого репозитория; если проблема сохраняется, создайте issue.

**В: Почему плагин такой большой?**

О: Он содержит полный шаблон автономного приложения, включая движок скриптов и нативные библиотеки для всех архитектур процессоров. Именно поэтому шаблон вынесли из основного приложения AutoJs6: этот объем несут только те, кто упаковывает приложения.

**В: Что такое "удаленная сборка"?**

О: Экспериментальный протокол, позволяющий плагину выполнять облегченную сборку в собственном процессе (распаковать шаблон, записать скрипт и настройки, переписать имя пакета и ресурсы, переподписать). В официальных выпусках она отключена; пока она адресована разработчикам, собирающим плагин самостоятельно.

### Техническая Справка

******

Разделы ниже адресованы разработчикам плагинов и интеграторам; для простого использования плагина они обычно не нужны.

#### Runtime Kit

Runtime Kit собирается основным репозиторием AutoJs6 и является единственным источником истины для шаблона автономного приложения. Этот плагин только проверяет и упаковывает этот артефакт; он не создает `template.apk`. Полный Runtime Kit обычно содержит эти файлы:

```text
template.apk
template.apk.sha256
default_key_store.bks
default_key_store.bks.sha256
runtime-kit.json
build-contract.json
public-api.txt
assets-manifest.json
native-libs.json
provenance.json
```

#### Идентификаторы Обнаружения

Хост обнаруживает и подключает этот плагин по следующим идентификаторам:

```text
Plugin ID:  autojs6-apk-builder-template
Engine:     apk-builder-template
Variant:    inrt-universal
Actions:    org.autojs.plugin.INFO / org.autojs.plugin.APK_BUILDER
Template:   org.autojs.autojs6.inrt
```

#### Локальная Сборка

Сначала создайте Runtime Kit в основном репозитории AutoJs6:

```powershell
.\gradlew.bat --console=plain :app:generateRuntimeKit
```

Затем соберите этот репозиторий с указанием созданного каталога Runtime Kit:

```powershell
.\gradlew.bat --console=plain :app:assembleRelease `
  -Pautojs.apkBuilder.templatePlugin.runtimeKitDir=<runtime-kit-dir>
```

Также можно распаковать опубликованный `autojs6-runtime-kit-*.zip` в `runtime-kit/` и собрать напрямую:

```powershell
.\gradlew.bat --console=plain :app:assembleRelease
```

#### Процесс Выпуска

Ожидаемый производственный процесс выпуска:

```text
AutoJs6 tag
-> main repository generates autojs6-runtime-kit-*.zip
-> main repository uploads the Runtime Kit to its GitHub Release
-> main repository dispatches SuperMonster003/AutoJs6-Plugin-APK-Builder-Template
-> this repository downloads and verifies the Runtime Kit
-> this repository builds the plugin APK
-> this repository uploads the plugin APK to the same tag Release
-> this repository records the pairing into compat-matrix.json
-> AutoJs6 Plugin Center installs this plugin
```

#### Подписание

Производственные выпуски плагина должны быть подписаны доверенным ключом подписи плагинов AutoJs6. Для выпусков GitHub Actions нужны эти секреты репозитория:

```text
SIGNING_KEY_BASE64
SIGNING_KEY_STORE_PASSWORD
SIGNING_KEY_ALIAS
SIGNING_KEY_PASSWORD
SIGNING_CERT_SHA256
```

Локальные сборки выпуска по-прежнему поддерживают игнорируемый корневой файл `sign.properties`:

```properties
storeFile=/absolute/path/to/release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

### Структура Ресурсов

******

```text
.readme/lang_*.json
.changelog/lang_*.json
.python/generate_markdown.py
app/src/main/res/values-*/strings.xml
app/src/main/res/raw-*/plugin_instruction.md
```

`strings.xml` содержит локализованные имена, описания и резервные инструкции плагина; `plugin_instruction.md` содержит инструкции, показываемые хостом.
